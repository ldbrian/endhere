# ADR-003: Question as Entry — V5 Strategic Refactor

- **Status**: Accepted
- **Date**: 2026-07-17
- **Supersedes**: V4 Constitution(已归档为 `constitution.v4.archived.md`,其与 V5 冲突的公理一律失效)
- **Carries forward**: ADR-002 Mirror 重定义核心(`Mirror is the memory layer of a living book`)—— V5 在其上叠加 `Mirror 是用户长期寻找答案过程中逐渐浮现的人生模式`,不冲突
- **Builds on**: ADR-001(ADR-002 顺手启用 = EndHere 第一份 ADR 体系)

---

## Context

V4 的产品路径:`留下碎片 → 长期积累 → Mirror → 看见自己`。

逻辑没错,但有致命短板:**用户不知道为什么要开始**。

「看见自己」是长期价值,第一次打开产品没即时收益。那整条路径就走不起来——没碎片,就没 Mirror,没价值。

V5 转轴:产品不再从「记录碎片」开始,而从「**用户正在寻找一个答案**」开始。

核心判断:

> **人生本身就是不断寻找答案的过程。**
> EndHere 希望成为一本**陪伴用户寻找答案的书**——不是告诉用户答案的书。

这不是改一处文案、改一个页面的功能改动。它改的是**价值入口**、**Page 语义**、**Response 职责**、**首页 Onboarding**、**产品语言全集** 一次。

---

## Decision

### D1. 价值入口转轴

V4:留下碎片为起点。
V5:**翻开书 + 遇见一个问题**为起点。

用户第一次使用即获得价值——问题本身被稍稍打开就成立,不依赖长期 Mirror 积累。

### D2. 使命重写

V4:`帮助用户通过人生碎片认识自己。`
V5:`帮助用户在生活和人生的问题中,更清晰地理解自己,并寻找属于自己的答案。`

### D3. Page 语义升级

V4 的 Page = 一页碎片(`BookPage.paragraphs`、`paragraphs[]` 是「留一句一句的碎片」)。
V5 的 Page = **一个问题的完整生命周期**(生命周期五段前置):Question / Reflection / Action / Echo / Mirror。

**本期不重构 Schema**(Priority 6 明示)。完整生命周期落在**上层语义**:
- `paragraphs[0]` 在 V5 上代表 Page 的「Question + 用户展开」。
- `paragraphs[0].trace` 在 V5 上代表 Response 的「Reflection」(帮问题变清晰)。
- 后续 Action / Echo / Mirror 段语义在本期**预留**,不在数据层落地。

> 这是为了保留可迁移性。未来 V5.5 决 Schema 时,数据可无缝向前迁移到分段容器。

### D4. Response 重定义

V4 Response:接住用户留下的这一句。
V5 Response:**帮助用户把进入页面时模糊的问题,离开时稍稍清晰一点。**

V5 Response 可以:

- ✅ 提供新的观察角度、拆解问题、识别情绪、提供不同可能性、提供可以尝试思考的方向。
- ✅ **适度**提出建议——必须以**可能性**形式,不是标准答案。「也许可以试着和对方聊聊」✅,「你应该去找他」❌。

V5 Response 不可以:

- ❌ 给正确答案、替用户做决定、输出鸡汤、强行积极、价值说教、心理诊断。

核心动词:**打开问题,而不是关闭问题**。正确的离开状态是——「这件事没解决,但我比刚翻开时清楚了一点」。

### D5. 首页 Onboarding

- 仅在 **001 页** 显示五选项卡片:
  - 一件让我烦恼的小事
  - 一个没想通的问题
  - 一段不知怎么处理的关系
  - 最近反复出现的念头
  - 自己写
- 任一页(含 001 之后所有页)的顶部:**书提问 / 引导一句**,下面用户手写。
- 用户点五选项后,书**追问**一句帮展开问题。例:点「一件让我烦恼的小事」→「可以慢慢告诉我,它为什么让你在意?」

### D6. 产品语言刷新

撤走旧语言:「碎片 / Fragment / 记录 / 记下来 / 日记 / Journal / Diary / 留下这句 / Mirror 是看见自己的层」。
接管新语言:「问题 / 翻开 / 想一想 / 写一写 / 页面 / 寻找答案 / Mirror 长期浮现模式」。

代码内的 `Fragment` type 名暂保留至 V5.5 重构 Schema 时一并改;**用户可见层**全部转新语言。

### D7. Mirror 再定义(不与 ADR-002 冲突)

V5 在 ADR-002 基础上再叠:

> Mirror 是**用户长期寻找答案过程中逐渐浮现的人生模式**。

ADR-002 解决「Mirror 是谁」:它是「书记忆层」。
ADR-003 解决「Mirror 做什么」:它是「浮现模式」。

两者并存,且 V5 constitution §3 第五段是终局描述。

## Consequences

### 正面

- **首层价值不再依赖长期积累**——用户翻开即打破价值入口为零的困境。
- **Response 职责更明确**、可对账——「打开问题」比「接住」更精确、也更难漂移到 Character.ai。
- Mirror 退一步,**仍是长期价值,不是唯一价值**——避免 V4 的「Mirror 收口不出来」的毒性。
- 产品语言与世界观一致——「书」「问题」「页面」最后能在用户心智中拼成一体。

### 负面 / 已知风险

1. **Schema 与语义对不上**:V5 把 V4 `paragraphs[0]` 当作「Question + 用户展开」复用,与字段名语义错位。短期可接受,长期在 V5.5 重 Schema 时偿还。
2. **五选项 Onboarding 引导强**:001 页放五选项卡片,会**轻度**引导用户分类型写问题。取舍:相比让用户面对一个纯空白张而走掉,这种体裁化引导是可接受的,但需避免用「类型」把未来页面也细分(那样会**封闭**用户),五选项仅出现在 001。
3. **Response 给建议的边界**——V5 解开了「适度建议」(以可能性形式),会引来诱惑。若 LLM 输出滑向「你应该…」,Response 重新漂回 Character.ai。必须有苦苦不肯给「闭合建议」的 prompt 设计。
4. **Legacy 词汇保留**——代码内 `Fragment` type,只在 V5.5 重 Schema 时清。长期与 V5 文档「不再出现 Fragment」承诺对不上,属于可接受的公告债。

### 不可越过的回退信号

- 若用户反馈「用了几页以后觉得这是一款 AI 心理咨询 / AI 助手」 —— V5 轴已漂移,_review 整批改动。
- 若 Response 输出里多次出现「你应该 / 你必须 / 你其实」 —— D4 边界破裂,prompt 必须加强约束,或人工审核。
- 若首页给的 5 选项变为长期行为/把每页都标题分类 —— D5 强求分类被滥用,五选项只在 001。

## Success Criteria

### 定性

1. 新用户第一页的点选率与「翻开 → 写一段」的 completion 率,应**显著高于** V4 他面对 Window prompt 的 completion 率。
2. 用户反馈里第一频词应是「**思考 / 想一下 / 清楚一点**」而不是「**记录 / 留下 / 积累**」。

### 失败信号

1. 用户合上书时的心态是「这个问题已解决」、而非「我对问题的理解比翻开时更具体了一层」 —— Response 漂入「闭合派」。
2. 用户识别 Mirror 为「分析工具 / 心理医」 —— Mirror 又漂回 V3 失败模式。

## 一句话总结

> 产品再次换轴:从「**记录碎片**」转为「**寻找答案**」。
> EndHere 不再是一本日记。
> 它是一本陪你寻答案的书 —— 而它从不替你写下那个答案。
