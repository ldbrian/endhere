# Windows 研究文档(原 Prompt Database)

> Status: 研究阶段,非实现。
> 配套: `constitution.md` 第一公理 + 第 3 节第一层(Expression)。
> 本文档不写一行产品代码。它的产出是**方法论 + 数据结构 + 40 条草案**,供真实用户验证后再落成 `windows.ts`。

---

## 0. 核心原则(写死,所有 Window 必须遵守)

> **好的 Window,不创造内容。**
> **好的 Window,只让用户注意到原本已经存在的东西。**

坏例(要求用户生产内容):
> 今天最难忘的一件事是什么?
> → 要回忆、要比较"最"、要组织语言、要进入情绪。

好例(让用户回头看一眼今天):
> 今天有没有一个东西,你一直放不下?
> → 内容本来就在,Window 只把注意力轻轻转过去。

判别:如果一个 Window 让用户**产生**了一段他原本没有的想法,它是内容生产工具(错)。
如果一个 Window 让用户**注意到**了一段他原本就有、只是没留意的体验,它是注意力转向工具(对)。

---

## 1. 为什么叫 Windows,不叫 Prompts

Prompt 暗示"问题"。问题有标准答案,有质量高低,会让人想"答好"。

Window 不是问题。它是**一扇打开的窗**:

- 「今天有没有一个声音?」打开的是**听觉**。
- 「今天有没有一个地方?」打开的是**空间记忆**。
- 「今天有没有一句话?」打开的是**语言记忆**。

我们研究的不是"提什么问",而是**进入生活的入口**。
Window 永远不创造生活,它只是让今天重新被看见。

## 2. L1–L5 量表(重新定义)

旧定义错误地用"需不需要回忆"做标尺。新定义用**认知动作**做标尺:

| 层级 | 认知动作 | 用户心里在做什么 | 例 |
|---|---|---|---|
| **L1 感知 Perceive** | 我有没有经历过? | 扫一眼,有/无 | 今天有没有一个声音让你回头? |
| **L2 选择 Choose** | 哪一个最明显? | 比较、筛选 | 今天哪一刻最让你想停下来? |
| **L3 表达 Describe** | 它是什么? | 概括、组织语言 | 那个声音听起来像什么? |
| **L4 理解 Interpret** | 它意味着什么? | 归因、解读 | 它为什么让你回头? |
| **L5 反思 Reflect** | 它改变了我什么? | 自我评估、提炼 | 这件事说明了我是谁? |

**关键边界(L1 → L2)**:
L1 允许"一秒钟的感官回忆"(声音让你回头,你想一下"啊,有")。

L1 **不允许**"解释、比较、概括、自我判断"。一旦出现"哪一个最 / 为什么 / 是什么样的 / 意味着",立刻升层。

**L1 边界精修版(更准)**:
L1 必须是对**自己直接经验的内省感知**。它不能借助任何**外部参照系**:

- ❌ **不能数**(如"重复了三次以上")→ 把感知外化成任务,用户从生活进入计数。
- ❌ **不能比基线**(如"比平时长 / 变慢了")→ 这就是 L2 选择,已经在比较。
- ❌ **不能猜他人的心**(如"别人没注意")→ 这是推测,不是感知。

判别:如果 Window 要求用户借助**计数器 / 基线 / 他人视角**才能回答,它已经不在 L1。
真正 L1 的答案是用户**直接内省**就能给出的,不依赖任何外部参照。

第一阶段(40 条)**全部 L1**,零 L2。理由:实验纯度。我们只研究"什么 Window 最容易留下第一块碎片",任何 L2 都会污染实验(分不清是 L2 好,还是用户已经准备好了)。L2 何时出现,等真实用户告诉我们。

## 3. 低摩擦问题的解剖

拆三个公认好用的 L1,找共同语法:

| Window | 指向 | 调动感官 |
|---|---|---|
| 今天有没有一个东西,你拿起来很多次? | 物品 + 动作 | 触觉 / 视觉 |
| 今天有没有一句话,你差点说出口? | 一句话 | 听觉(内在) |
| 今天有没有一个地方,让你停留了两分钟? | 地点 + 动作 | 空间 / 身体 |

共同语法骨架:

```
今天有没有  +  [一个具体的感官对象]  +  [一个轻量的状态/行为]?
   ↑                  ↑                          ↑
 存在性检查        具象、可感知              不要求解释
(yes/no)         (不是抽象概念)         (只问"有没有")
```

四个识别特征:
1. **以"今天有没有"开头** —— 存在性检查,答案是有/无,不是论述。
2. **指向一个具体感官对象** —— "一个东西 / 一句话 / 一个地方 / 一个声音",不是"一种感觉 / 一段经历"。
3. **附一个轻量状态或行为** —— "拿起来很多次 / 差点说出口 / 停留两分钟",提供抓取的把手。
4. **指向已经发生的事** —— 内容在用户身上已存在,Window 只让它被注意。

反例(违反骨架):
- "今天感觉怎么样?" → 无具体对象,要求概括(L3)。
- "今天最重要的事?" → "最"触发比较(L2)。
- "为什么今天累?" → 要求归因(L4)。

## 4. 两个研究维度

两个维度测的是完全不同的事,打标签时分别判断:

> **object_type 回答:你注意到了什么?**(对象)
> **Sense 回答:你是怎么注意到它的?**(感官通道)

### 维度 A · object_type —— 你注意到了什么?
纯多标签,无主次。研究标签要客观,不让人为「主对象」判断掺水。
取值:人物 / 物品 / 动作 / 一句话 / 声音 / 地点 / 气味 / 身体 / 时间 / 影像 / 泛

### 维度 B · Sense —— 你是怎么注意到它的?
纯多标签。Mirror 最终看的是生活,生活首先来自感官。
取值:视觉 / 听觉 / 触觉 / 嗅觉 / 味觉 / 身体感觉 / 空间 / 时间 / 内在

### 举例

| Window | object_type | Sense |
|---|---|---|
| 今天有没有一句话,你一直记得? | 一句话 | 听觉 |
| 今天有没有一个地方,你站了很久? | 地点 | 空间, 身体感觉 |
| 今天有没有一个东西,你拿起来很多次? | 物品, 动作 | 触觉, 视觉 |

## 5. 数据结构提案(最小可用,不过度设计)

> 警告:不要在不懂用户之前堆字段(宪法精神:不造一堆用不上的数据)。
> 第一版只留**研究必需**字段,其余标为 optional,等数据说话再加。

```ts
type Window = {
  text: string;                  // Window 文案
  level: 1;                       // 第一阶段锁死 L1
  object_type: ObjectType[];      // 纯多标签,无主次
  sense: Sense[];                 // 纯多标签
  language: 'zh' | 'en';          // 默认 'zh'
};
```

**字段纪律(宪法精神)**:产品先长行为,再长数据结构。第一版只留**现在就有地方真正用到**的字段。任何"以后可能用到"的字段一律不进。

**故意不放入第一版的字段**:
- `emotion`:已确认不是研究维度(宪法 + 你的判断)。
- `season`:大多数 Window 是季中性的;以后按需。
- `time_of_day`:以后按需。
- `weight`:第一版均等权重即可;等真实完成率数据出来,再让 weight 从数据里长出来。

## 7. 分布观察(给真实数据验证用)

40 条草案的感官覆盖(粗算):

| Sense | 出现次数 | 观察 |
|---|---|---|
| 视觉 | ~18 | **偏多**,符合"视觉是主导感官",但可能过载 |
| 听觉(含内在) | ~11 | 适中 |
| 触觉 | ~10 | 适中 |
| 空间 | ~8 | 适中 |
| 身体 | ~9 | 适中 |
| 时间 | ~9 | 适中 |
| 嗅觉 | 2 | **偏少**,以后可补 |
| 味觉 | 1 | **偏少**,以后可补 |

| object_type | 出现次数 | 观察 |
|---|---|---|
| 物品 | ~13 | 物品是低摩擦最强的入口(具体、可触、可数) |
| 动作 | ~16 | 动作词提供"把手",低摩擦的关键 |
| 地点 | ~7 | |
| 人物 | ~8 | |
| 一句话 | ~8 | |
| 声音/气味/身体/时间 | 分散 | |

**研究假设**(等真实数据验证):
1. **物品 + 动作** 组合的 Window 完成率最高(具体 + 有把手)。
2. **嗅觉 / 味觉** Window 完成率可能偏低,但一旦回答,**碎片丰富度**可能更高(感官记忆触发联想)。
3. **"今天有没有"开头** 的存在性句式,比任何其他句式完成率都高。

这三个假设都不预判答案,等数据。

## 8. 下一步(研究 → 实现的边界)

本文档是**研究终点**,不是**实现起点**。实现起点必须满足:

1. 40 条落成 `windows.ts`,带 type-safe 的 `object_type` / `sense` 枚举。
2. WritePanel 改造:**只显示一条 Today's Window**,不堆列表。
3. 双入口:「回答这个」(带 window 进 `/new`)+「我想写别的」(空进,window 退场)。
4. 「换一个」:加权随机(默认 `weight=1`,以后按完成率调权)。
5. **埋点**:每条 window 的 `impression / answered / skipped / swapped`,用于验证第 7 节假设。

**埋点的伦理边界(第一公理约束)**:埋点只记录 Window 自身的存活率,**绝不**记录用户写了什么。用户的内容永远是主角,Window 只是被研究的对象。
