## 0. 一句话

把「揭示」的权限从段级收回到页级：**补充时只有批注，宣告讲完整后才有一次翻牌＋金句。**
一页只揭示一次，由机制保证，不靠 prompt 祈祷。

---

## 1. 页弧与权限

| 步骤 | 触发 | 谁在动 | 允许 | 禁止 |
|---|---|---|---|---|
| 补充（接住） | 每次写完一段 | 书 | 1 句批注 ≤60 字；可带**往下展开**的追问 | 给结论、下判断、翻牌、问「所以这说明什么」 |
| 讲完整（宣告） | 用户点「这一页讲完了」 | 用户 | —— | AI 判定讲完了 |
| 翻牌＋金句（揭示） | 宣告之后 | 书 | 全页唯一一次揭示：牌＋解读词＋金句＋标题 | 建议、替用户定论 |
| 合上（收束） | 用户点「合上」 | 用户 | 全屏缩回书里，一页归档 | 自动关 |

**段级追问的判别尺**：追问之后用户能**继续讲更多事实**＝对；只能**同意或不同意书的判断**＝错。

## 3. API 契约（同一个 route，两种 mode）

`POST /api/book/organize`

### mode = `segment`（缺省，向后兼容）

入参：`original_content`、`conversation_history`、`persona_preferences`
出参：

```jsonc
{
  "narration_content": "…",   // 兼容旧客户端，等于 annotation
  "annotation": "…",          // 1 句，≤60 字
  "question": "后来呢？",      // 可空；只能往下展开
  "persona": "Echo"
}
```

### mode = `page`

入参：整页全部段落（`paragraphs: string[]`）+ 全部段级批注 + `persona_preferences`
出参：

```jsonc
{
  "title": "深夜那碗面",         // ≤8 字，只提炼原话里的意象
  "quote": "有些累，是一层一层压上来的。", // 金句，落页
  "card_id": "layer",           // 必须是 10 张枚举之一
  "card_reading": "你说的不是那一件事，是很多件都没说出口的事叠在一起。",
  "persona": "Echo"
}
```

**硬约束**
- `title` **必须在页级返回里**（与金句同一次调用生成）：≤8 字、只提炼用户原话里的意象、不引申不下判断；用户可改；生成失败或不合适时回落本地首句提取（老页没有页级调用，继续用本地提取）
- `card_id` 不在枚举内 → 直接按 `persona` 偏好选一张兜底，不让自由命名（否则一页一个说法，牌就不成立）；**兜底触发时记一条日志**（`console.warn`，只留痕供事后发现模型漂移，不对用户展示）
- `persona` 也必须在六人枚举内，否则回落 `Echo`
- 两个 mode 各自的限流计数器：`segment` 25 次/小时/IP、`page` 10 次/小时/IP（现状 6 次/小时在拿「一页」的预算跑「一句批注」）
- 429 时 `segment` 返回明确的可重试信号，前端文案不能伪装成书的语气（现状：「这一页，书先接住了。」其实是配额用完）

## 4. 三个文本元素怎么呈现（本节为定义，不是建议）

| | 牌 | 解读词 `card_reading` | 金句 `quote` |
|---|---|---|---|
| 出现时机 | 第一 | 第二（含落款「Echo 解牌」） | 第三，最后 |
| 翻牌时刻 | 卡背线条 → 彩色显影 0.8s | 牌之后缓入 | 解读词之后，单独一行、字号最大 |
| 篇幅 | —— | **1–2 句，宜短** | 一句 |
| **是否落页** | **是**（成为页的永久插画） | **否** | **是** |
| 读态可见 | 是 | 否 | 是 |

**解读词为什么必须短**：它是翻牌过程中的一句话，越短越不抢金句的高潮地位。金句是这一页唯一的「被留下的话」，解读词长了就会变成第二个结论。

**为什么解读词不落页**：解读词是「这一刻对你说的话」，与段级批注同属写态；落页的痕迹必须是一张图＋一句。
三者全落页会让页上出现三段书的话，用户的话变少数——回应的分量就不再「配得上」留言，而是压过留言。
时序错开（牌→解读词→金句）也解决了「三个文本抢注意力」：它们在时间上排队，空间上金句独占一行。

**落款要分清两件事**（容易混淆，写死在这里）：
- **落款的人名落页**：「Echo 解牌」跟在金句旁，是这一页的落款，读态可见
- **落款之外的解读词正文不落页**：`card_reading` 那句话只在翻牌时刻出现，读态看不见
即：页上留下的是「一句金句 ＋ 一行『Echo 解牌』」，不是「一段解牌词」。

## 5. 正文合成规则（硬约束）

**正文只能是用户原话拼接**：按段落 `paragraphs[].text` 顺序连起来，中间补标点与换行。
**绝不能让 LLM 改写、润色、缩写。**「话不能代笔」与「问题可以给，话不能代笔」同源。
技术上：`quote` / `title` 可以生成，`正文` 永远来自 `paragraphs.map(p => p.text)`，代码里不存在让模型碰它的路径。

## 6. 交互：宣告 → 到达感 → 翻牌 → 合上

1. 页内有内容时，页底出现明确动作：**「这一页讲完了」**（不点就永远只有批注，绝不自动翻）
2. 点击 → 按钮锁死变「正在读…」→ 发 `mode:'page'`
3. **到达感**：目标 1–2 秒。响应比 1.2s 快时补足到 1.2s；超过就直接进翻牌——**不做假等待**（超时假装更慢是欺骗，比慢更坏）
4. **翻牌**：卡背线条 → 彩色显影 0.8s（视觉方向第三节：写完抽卡后把卡里的画移到书页上）
5. 解读词缓入 → 金句缓入 → 标题落到页眉
6. 按钮变**「合上」**；点击才 `finalizeCurrentPage` 并缩回书里
7. 任一步失败：保留「这一页讲完了」可重试，页面不前进、不吞掉内容

## 7. 非破坏迁移（Brian 已定：不接受清空）

**根因**：`storage.ts:491-563` 现在的 migrate 会把所有旧页塞进 `legacyArchive` 并重置为空书。只要为加字段 bump 版本，所有人的书就被清空。

**方案**

```ts
version: 6,
migrate: (persistedState, fromVersion) => {
  if (!persistedState) return persistedState;

  // A. 结构兼容 → 原地保留，一页都不动
  if (isCompatibleBook(persistedState.book)) {
    // 只补可选字段的默认值：reveal / declared_at 缺失即「没翻过牌，不是漏数据」
    return persistedState;
  }

  // B. 真正旧格式（V4 及以前）才走归档
  return legacyConvert(persistedState); // 现有 migrate 的转换逻辑，原样保留
},
```

**`isCompatibleBook` 判定**：`book.pages` 是数组，且每页有 `id` / `pages[].paragraphs` 是数组 / `page_number` 是字符串。
满足即视为当前结构（因为新字段全是可选的）。

**写入安全（先写新结构、验成功再切版本、失败回滚）**

```ts
function commitSafe(next: unknown, fallback: unknown) {
  const json = JSON.stringify(next);
  const probe = 'endhere_probe_key';
  try {
    localStorage.setItem(probe, json);        // ① 先写到探针键
    const ok = localStorage.getItem(probe) === json; // ② 读回校验
    localStorage.removeItem(probe);
    return ok ? next : fallback;               // ③ 成功才切版本，失败原样返回
  } catch {
    return fallback;                           // 配额满 / 禁用 → 不切版本，数据不动
  }
}
```

失败时 `return persistedState`，版本停在 5，下次再试。

**旧页不补翻牌**：`reveal` 缺失就是缺失。不给旧页事后补一张牌——宣告权在用户手里，替旧页补牌等于替用户宣告「你讲完了」。
UI 表现：无 `reveal` 的页不渲染插画区，是纯文字页（不留空洞占位）。

## 9. 美术生产方式（先定，否则 P1 会卡住）

**结论：AI 生成＋你把关，但 P1 不等美术。**

理由：
- 10 张牌 × 2 版（彩色／去色线条）＝ 20 个资产，画师单张报价按 300–800 算就是 3–8k，且改稿周期长；当前视觉方向自己写着「样稿为示意画风，非终稿美术」，还在探索期
- 真正会卡住 P1 的不是画，是**资产契约**。把契约先定死，画什么时候到都不影响机制跑通

**资产契约**（代码只认这四个路径，换画师只换文件不动代码）

```
public/cards/{cardId}-color.webp   // 落页插画（彩色，水彩）
public/cards/{cardId}-line.webp    // 翻牌过程中的线条版
public/cards/card-back.webp        // 写态占位：中性卡背纹样（绝不能是某张牌的线条版）
```

**推进顺序**：路已有 demo → 先定这一张的风格基准 → 批量出剩下 9 张 → 统一调色。
每张过一关再下一张（AI 水彩最容易整批风格漂移）。线条版由彩色版做**同一画面的去色工序**，不重画。

**P1 期间用占位**：先用程序化 SVG（单色描线＋纸纹）填上这四个路径，机制先跑通；美术到位后替换文件即可。
